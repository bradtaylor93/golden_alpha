# Diagnostics and Projection Discipline

Diagnostics are first-class artifacts generated by explicit `DiagnosticNode` instances.

Examples:

- `train_test_deviance_gap`
- `feature_drift`
- `residual_std_by_asset`
- `prediction_disagreement`
- `coefficient_stability`
- `calibration_gap`

## Why explicit projection exists

Fold-level diagnostics cannot be merged into row-level features implicitly.
If you want model inputs from diagnostics, use a `ProjectionNode`.

```
[DiagnosticArtifact]
      |
      v
[ProjectionNode(lag=1)]
      |
      v
[FeatureTableArtifact projected diagnostics]
```

The lag ensures causal use:

- diagnostic info from prior windows only
- no same-row forward contamination

## Example

```python
ProjectionNode(
    name="projected_health",
    depends_on=("diag_ret", "bars"),
    inputs=ProjectionInputs(
        diagnostic_tables=["diag_ret"],
        bars=["bars"],
        lag=1,
    ),
)
```
